# LandShield

> Tamper-evident deed verification, fraud detection and citizen pre-purchase checks for Bangladesh land records.
> LandTech Innovation Hackathon 2026 | Track: Digital Land Records, Verification & Digitization
> Problem statements: P2 (primary), P3, P4, P5 | Bonus: P1 (Phase 2)

[Live demo](URL) | [Demo video](URL) | [Concept note](docs/concept-note/CONCEPT_NOTE.pdf) | [Pitch deck](URL)
Release: `v1.0-round1` (Round 1) | `v2.0-final` (Final)

> **Data notice:** all data in this project is synthetic. No real personal data or real land records are used, and no government system is scraped or tested.

## 1. Problem
2-3 sentences: land disputes, forged deeds, double-selling, records split between registration and mutation, survey generations (CS, SA, RS, BS).

## 2. Our solution
One paragraph: a verification and reconciliation layer on top of existing land systems, not a replacement.
Principle: rules and integrity checks decide, ML advises, AI explains.

## 3. Key features
**Round 1 (core)**
- Signed (Ed25519), hash-chained deeds with QR verification (VALID / TAMPERED / SUPERSEDED / CANCELLED / UNKNOWN)
- Tamper Lab demo (edit one field, see TAMPERED instantly)
- Fraud engine R1-R6: oversold/double sale, seller not owner, missing mutation, rapid transfers, integrity failure, flagged land; explainable 0-100 score in Bangla and English
- Registration blocked on critical findings (HTTP 409 with reasons); alerts for officers
- Mutation workflow with auto-checks, officer override notes and audit trail
- Citizen "check before you buy" page, registrar, officer and admin pages

**Final (additions, feature-flagged)**
- Cross-office reconciliation (R8) and survey lineage graph CS-SA-RS-BS (R7)
- Offline-verifiable QR (works with no network)
- AI due-diligence report in Bangla (facts from the engine, AI only rewrites, template fallback)
- Role-based privacy views, Merkle transparency log
- Attack-simulation suite and evaluation metrics page
- ML advisory second opinion (LightGBM + SHAP) and scan-to-ingest (bonus, if included)

## 6. Quick start
```bash
git clone <repo> && cd landshield
cp .env.example .env
docker compose up --build -d
docker compose exec backend python -m scripts.seed --reset
# Final version also: python -m scripts.seed_phase2
```
Open http://localhost:3000 (frontend) and http://localhost:8000/docs (API).

Manual setup:
```bash
make setup      # venv + dependencies
make seed
make run        # backend
cd frontend && npm install && npm run dev
```
Useful targets: `make test`, `make smoke`, `make attack`, `make evaluate`, `make train` (Final), `make up`, `make down`, `make reset`.

## 7. Configuration
Copy `.env.example`. Never commit `.env` or `keys/`.
| Variable | Purpose |
|---|---|
| DATABASE_URL | database connection |
| JWT_SECRET, JWT_EXPIRE_MINUTES | auth (app refuses the default secret when DEMO_MODE is false) |
| SIGNING_KEY_PATH / SIGNING_KEY_HEX | Ed25519 signing key (file locally, env on cloud) |
| DEMO_MODE | enables Tamper Lab and dev routes (false in public deployments) |
| ALLOWED_ORIGINS, FRONTEND_URL | CORS and QR links |
| SEED_ON_START | seed empty database at first boot |
| FEATURE_RECONCILE / LINEAGE / OFFLINE_QR / AGENT / TRANSPARENCY / ML / OCR | Final-round features |
| LLM_PROVIDER, LLM_MODEL, LLM_API_KEY | AI report and OCR (optional; template fallback if empty) |

## 9. Data sources and privacy
- All data is generated by our own scripts (Faker + invented Bangla names and places).
- Public pages show masked names; officers see full synthetic names. No NIDs, phone numbers or real addresses exist anywhere.
- No scraping, automated querying or testing of any government or third-party system.
See [docs/SECURITY.md](docs/SECURITY.md) and [docs/DATA_POLICY.md](docs/DATA_POLICY.md).

## 12. Limitations (honest)
Prototype keys (no HSM yet); hash chain gives tamper evidence, not prevention (Merkle log helps); simplified mutation workflow; heuristic rules; metrics on synthetic data; offline QR cannot show whether a newer sale exists.
